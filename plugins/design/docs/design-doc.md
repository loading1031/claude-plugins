# 로컬 디자인 문서

와이어프레임과 화면 디자인은 프로젝트 루트 `design/`에 둔다. HTML 진입점, SVG, 수정 가능한 원본을 저장소에서 함께 관리한다. 이 플러그인은 문서 구성과 코드 연결을 정하고, UI 코드 규칙은 프로젝트와 프레임워크별 플러그인(예: `nextts`, `django`)을 따른다.

## 선언과 산출물

`/design:init`이 프로젝트 `CLAUDE.md`에 기록한다.

```markdown
## 디자인
- 문서: design/index.html
- 기준: 없음
```

- `design/index.html`을 로컬 미리보기의 진입점으로 둔다. 사용자가 지정한 다른 프로젝트 내부 경로가 있으면 따른다.
- 문서의 탐색 UI·CSS·스크립트·SVG와 수정 원본은 프로젝트에서 재현 가능하게 둔다. 단일 HTML, 여러 페이지, 기존 프로젝트 빌드 중 필요한 만큼 사용하며 새 프레임워크나 서버를 필수로 도입하지 않는다.
- 바로 여는 HTML이 기본이다. 서버나 빌드가 필요하면 실행 방법과 원본 위치를 짧게 안내한다. 기존 UI 프레임워크·테마·컴포넌트를 사용하고, 외부 CDN·별도 계정에 미리보기를 의존시키지 않는다.
- 에이전트가 파일을 직접 생성·연결한다. Claude 아티팩트나 Claude Docs 로그인·커넥터·토큰, 사용자 수동 업로드는 이 흐름의 선행 조건이 아니다.
- 기존 외부 디자인은 참고 자료로 읽을 수 있다. 필수 참고 자료를 읽지 못하면 사용자에게 접근 가능한 링크나 파일을 요청한다. 기존 외부 문서와 프로젝트 자료를 임의로 삭제하지 않는다.

## 설계 순서와 탐색 구조

먼저 전체 IA(정보 구조)와 주요 사용자 흐름을 작성하고, 화면 목록과 각 화면을 설계한다. 컴포넌트와 토큰은 그 아래에 둔다.

```text
화면                  ← 개요: 전체 IA, 사용자 흐름, 화면 목록
├ 대시보드            ← 목적·설명 + 와이어프레임
├ 종목 차트
└ 컴포넌트            ← 개요: 공통 컴포넌트 목록
   ├ 버튼
   ├ 차트 카드
   └ 토큰             ← 색·간격·글꼴·둥글기
```

- 왼쪽 사이드바에 화면별 페이지 이름을 표시한다. 선택하면 해당 화면의 설명과 와이어프레임이 열린다. 좁은 화면에서는 접거나 상단 메뉴로 바꿀 수 있다. 문서 탐색 메뉴와 제품의 실제 메뉴를 구분한다.
- 화면 설명에는 목적, 진입·복귀 경로, 주요 행동, 로딩·빈 값·오류·권한 등 관련 상태, 확정 규칙과 미정 사항을 적는다. 개요의 흐름과 화면 사이 이동이 일치해야 한다.
- 그림은 실제 SVG 도형·텍스트 또는 HTML/CSS로 작성한다. PNG를 감싼 SVG는 벡터 와이어프레임으로 취급하지 않는다. 사진·렌더 이미지에는 비트맵을 사용할 수 있다. SVG 구조안과 실제 UI 프레임워크로 렌더한 시안은 구분해 설명한다.
- 도형·텍스트를 지나치게 축소하지 않는다. 필요하면 흐름을 여러 그림으로 나누거나 확대·가로 스크롤을 제공한다.
- 공통 컴포넌트는 공유 원본을 참조한다. HTML 템플릿·공유 컴포넌트·SVG 참조 등을 사용할 수 있으며, 정적 빌드라면 공통 원본 수정 후 관련 화면을 함께 재생성한다.

## 무엇이 기준인가

| 자료 | 기준 | 흐름 |
|---|---|---|
| 토큰 | 프로젝트 코드의 테마·토큰 파일 | 실제 값을 코드에서 바꾸고 문서에 반영한다. 코드가 없으면 미정으로 둔다 |
| 컴포넌트 | 프로젝트 UI 컴포넌트 코드 | 문서에는 목록·쓰임새·그림을 두며 실제 모습은 코드가 정한다 |
| 화면 | 승인된 로컬 디자인 문서 | IA·흐름·와이어프레임을 먼저 정하고 구현이 승인 기준을 따른다 |

## 기준과 변경 이력

- 문서·SVG·소스를 Git으로 함께 관리한다. 자동으로 증가하는 Claude Docs의 탭 rev·그림 pub은 사용하지 않는다.
- 사용자가 승인한 디자인은 실제 Git 커밋/태그와 관련 파일 경로로 식별한다. Git을 사용하지 않으면 승인된 스냅샷 경로를 기록한다. 승인 전에는 `기준: 없음`을 유지하며 커밋·태그·스냅샷을 임의로 만들어 승인되었다고 표시하지 않는다.
- 화면 구현 전에 선언된 기준에서 화면과 참조 컴포넌트를 읽는다. 현재 문서와 승인 기준이 다르면 관련 차이를 확인하고, 지시가 명확하지 않은 경우 사용자에게 기준을 묻는다.
- 구현 커밋을 작성할 때 반영한 문서와 승인 기준을 기록한다. 예: `디자인: design/index.html#dashboard, 기준 <승인 커밋>`.
- 디자인 수정 시 관련 화면·공유 컴포넌트·문서의 연결을 함께 갱신한다. 새 기준은 사용자 승인 후 기록한다. 이 플러그인이 커밋·공개 게시를 별도로 승인하는 것은 아니다.

## 미리보기와 확인

가능한 로컬 미리보기를 열어 IA·화면 탐색, SVG 가독성, 관련 화면 상태를 확인한다. 도구가 해당 미리보기를 지원하지 않으면 그 한계를 보고하고, 파일 생성·빌드 성공을 시각 검증으로 표시하지 않는다. 결과에는 실제 진입 파일의 절대경로 링크와 확인 범위를 포함한다.
