# 디자인 문서

와이어프레임과 화면 디자인은 저장소가 아니라 Claude 아티팩트(Claude Docs 문서)에 둔다. 이 플러그인은 그 문서를 어떻게 구성하고 코드와 어떻게 맞추는지만 정한다. 코드 규칙(Tailwind, UI 컴포넌트, 접근성)은 프레임워크별 플러그인(예: `nextts`)이 맡는다.

## 선언

프로젝트 `CLAUDE.md`에 `/design:init`이 쓴다.

```markdown
## 디자인
- 문서: https://claude.ai/code/artifact/<id>
- 기준: 대시보드 rev 3, 종목 차트 rev 5, 버튼 pub 2, 차트 카드 pub 5
```

- 화면을 만들기 전에 그 화면 탭을 기준 rev로 읽는다. 탭이 넣어 둔 컴포넌트 그림도 읽는다.
- 구현한 커밋 본문에 반영한 탭 rev와 그림 pub을 적는다: `디자인: 대시보드 rev 3, 버튼 pub 2`
- 디자인을 확정하면 "기준" 줄을 지금 rev·pub으로 고친다.

## 탭 구성: 전체가 부분을 품는다

화면이 컴포넌트를 쓰고 컴포넌트가 토큰을 쓰므로, 메뉴는 화면이 위, 토큰이 가장 아래다.

```
화면              ← 최상위. 개요: 화면 목록
├ 대시보드
├ 종목 차트
└ 컴포넌트        ← 개요: 컴포넌트 목록
   ├ 버튼
   ├ 차트 카드
   └ 토큰         ← 색·간격·글꼴·둥글기
```

- 컴포넌트는 여러 화면이 같이 쓰므로 특정 화면 아래가 아니라 화면 목록과 같은 줄의 묶음이다. 토큰도 같은 이유로 컴포넌트 묶음 맨 아래다.
- 화면 탭에는 그 화면이 쓰는 컴포넌트 그림을 직접 넣는다(embed). 탭이 달라도 같은 그림을 참조할 수 있어서, 컴포넌트 그림을 고치면 넣어 둔 모든 화면에 반영된다.

## 무엇이 기준인가

| 탭 | 기준 | 흐름 |
|---|---|---|
| 토큰 | 코드(`globals.css`의 `@theme`) | 값은 코드에서 바꾸고, 문서 탭은 코드에서 읽어 다시 만든다 |
| 컴포넌트 | 코드(UI 컴포넌트 폴더) | 문서에는 목록·쓰임새·그림. 실제 모습은 코드가 정한다 |
| 화면 | 문서 | 와이어프레임이 먼저, 코드는 선언된 rev를 따른다 |

## 버전

2026-10-14 테스트 문서로 확인한 내용:

- 탭은 수정할 때마다 rev가 오른다. Claude는 예전 rev를 읽을 수 있고(`atRev`), 그 뒤 다른 수정이 없으면 탭을 되돌릴 수 있다.
- **그림을 고쳐도 탭 rev는 오르지 않는다.** 탭 rev는 본문 글과 그림 위치만 기록하고, 그림은 따로 pub 번호를 가진다(게시할 때마다 오름). 그래서 기준을 적을 때 탭 rev와 그림 pub을 같이 적는다.
- 그림의 예전 pub을 읽거나 되돌리는 방법은 아직 확인하지 않았다.
- 태그·브랜치·병합은 없다.
