# 로컬 디자인 문서

근거: `${CLAUDE_SKILL_DIR}/../../docs/design-doc.md`. 디자인은 프로젝트 루트 `design/`의 HTML·SVG와 수정 가능한 원본으로 관리한다. Claude 아티팩트나 Claude Docs 도구를 전제로 하지 않는다.

프로젝트 `CLAUDE.md`의 "## 디자인" 절(로컬 문서 경로, 승인 기준)을 따른다. 절이 없으면 기존 `design/`를 확인하고 `/design:init` 절차로 연결한다.

- 화면 구현 전에 승인 기준의 화면 설명·와이어프레임과 참조 컴포넌트를 읽는다. 승인 기준과 현재 문서가 다르고 어느 쪽을 따를지 명확하지 않으면 사용자에게 확인한다. 승인 전 초안을 확정된 기준으로 표시하지 않는다.
- 문서 구성은 전체 IA·사용자 흐름 → 왼쪽 화면별 페이지 → 각 화면의 설명·와이어프레임 순서를 따른다. `화면` 아래 화면별 페이지와 `컴포넌트`, `컴포넌트` 아래 컴포넌트별 페이지와 `토큰`을 둔다.
- 와이어프레임은 실제 SVG 또는 HTML/CSS로 만든다. PNG를 SVG 안에 넣어 벡터처럼 표시하지 않는다. 사진·렌더 이미지 등 비트맵 에셋은 필요에 따라 쓴다. 문서 폭 때문에 글자가 읽기 어려워지면 그림 분할·확대·영역 스크롤을 제공한다.
- 프로젝트의 기존 UI 프레임워크·테마·컴포넌트를 재사용한다. 토큰·컴포넌트의 실제 값은 코드가 기준이며 문서는 코드를 읽어 갱신한다. 화면 구성은 디자인 문서가 기준이다.
- 여러 화면의 공통 컴포넌트는 공유 소스·템플릿·참조로 연결한다. 정적 생성물이면 공통 원본을 고친 뒤 관련 화면을 재생성한다. 그림 복사본을 화면별로 따로 유지하지 않는다.
- 로컬 파일을 직접 수정하고 상대경로·자산 연결을 유지한다. 사용자가 파일을 하나씩 업로드하도록 요구하지 않는다. 참고 외부 문서가 필수인데 읽을 수 없으면 자료 접근을 요청한다.
- 문서와 SVG 변경은 Git으로 함께 추적한다. 구현 커밋을 만들 때 반영한 문서 경로와 승인 기준 커밋/태그를 기록한다. 사용자가 디자인을 확정하면 "기준"을 실제 승인 버전으로 갱신한다. 별도 rev·pub 번호를 만들어 운영하지 않는다.
- 가능한 미리보기에서 렌더링·화면 탐색을 확인하고 확인한 범위를 보고한다. 빌드 성공과 시각 검증을 구분한다.
- 화면 검토 결과를 원본 HTML에 연결해 공유해야 하면 `design/review.html` 형태의 로컬 리뷰 아티팩트를 만든다. 심각도·화면 코드·근거·사용자 영향·최소 수정안을 의견마다 기록하고, 선택 시 원본 화면으로 이동하게 한다. 검토 아티팩트는 승인 기준 문서와 분리하고 승인 상태로 오인되지 않게 표시한다.
