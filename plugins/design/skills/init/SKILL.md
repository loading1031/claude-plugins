# /design:init — 로컬 디자인 문서 초기화

근거: `${CLAUDE_SKILL_DIR}/../../docs/design-doc.md`.

## 1. 기존 자료와 범위

- 프로젝트 지침과 `CLAUDE.md`의 "## 디자인" 절을 읽고, 루트 `design/`와 기존 디자인 자료를 확인한다. 기존 폴더가 있으면 재사용하고 사용자 변경을 보존한다.
- 인자나 프로젝트 설정의 기존 문서 경로·참고 링크를 읽는다. 외부 문서는 참고 자료로 사용하며 새 산출물은 프로젝트에 저장한다. 필수 참고 자료를 읽을 수 없으면 접근 가능한 링크나 파일을 사용자에게 요청하고, 그 내용을 추정해 설계를 진행하지 않는다.
- 사용자가 말한 화면 범위를 사용한다. 범위가 없어 초기 문서만 만들 때는 화면 자리를 임의의 제품 기능으로 채우지 않는다.

## 2. 로컬 문서 생성·연결

- 프로젝트 루트 `design/` 아래에 `index.html` 진입점을 만든다. 사용자가 다른 프로젝트 내부 경로를 명시하면 그 경로를 따른다. Claude 아티팩트 생성·로그인·토큰 발급·수동 파일 업로드를 요구하지 않는다.
- 기존 로컬 문서가 있으면 연결하거나 필요한 부분만 수정한다. 기존 자료의 이동·이름 변경이 필요하면 차이를 보여 주고 먼저 확인한다. 내용을 일괄 이동·삭제하지 않는다.
- 전체 IA(정보 구조)와 주요 사용자 흐름을 개요에 먼저 둔다. 왼쪽 사이드바에는 `화면` 아래 화면별 페이지와 `컴포넌트` 묶음, 그 아래 컴포넌트별 페이지와 `토큰`을 둔다. 단일 HTML의 해시 탐색이나 여러 로컬 파일 중 프로젝트에 맞는 방식을 쓴다.
- 각 화면은 설명과 실제 SVG 또는 HTML/CSS 와이어프레임을 함께 제공한다. 컴포넌트와 토큰은 프로젝트 코드에서 읽으며 프레임워크별 규칙을 따른다. 토큰 코드가 없으면 미정으로 남긴다.
- 에이전트가 파일과 연결을 직접 만든다. HTML은 바로 열 수 있게 하고, 서버가 필요한 방식이면 실행 방법을 함께 제공한다. 의존 자산은 `design/`에 포함하거나 프로젝트의 빌드로 생성한다.

## 3. CLAUDE.md

프로젝트 루트 `CLAUDE.md`에 아래 절이 없으면 추가하고, 있으면 해당 값만 맞춘다. 다른 내용은 건드리지 않는다.

```markdown
## 디자인
- design 플러그인을 따른다 (화면 작업 전 로컬 문서를 읽고, 구현에 반영한 기준을 기록한다)
- 문서: design/index.html
- 기준: <사용자가 승인한 Git 커밋/태그 또는 스냅샷 경로. 아직 없으면 "없음">
```

기존 외부 문서 링크는 필요하면 `참고`로 남기고, 로컬 문서 경로를 구현 진입점으로 설정한다. 실제로 승인·생성되지 않은 기준을 적지 않는다.

## 4. 결과

문서의 절대경로 링크, 생성·수정한 페이지, CLAUDE.md에 쓴 값과 확인 범위를 알린다. 가능한 로컬 미리보기를 열고 렌더링을 확인한다. 도구가 해당 미리보기를 지원하지 않으면 미확인 범위를 명시한다. 파일 생성이나 빌드 성공을 시각 검증으로 보고하지 않는다.
