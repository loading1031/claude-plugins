# 선택 기능: HTMX

프로젝트가 HTMX를 사용하거나 부분 HTML 갱신을 요청한 경우에만 적용한다. 기본 Django 화면에 HTMX 설치를 강제하지 않는다.

- 일반 요청은 전체 페이지, HTMX 요청은 필요한 HTML 조각을 돌려준다. 같은 URL에서 두 응답을 제공하면 HX-Request에 대한 Vary와 캐시 분리를 확인한다.
- hx-target/hx-swap을 실제 DOM과 맞추고 전체 페이지 HTML을 조각 대상 안에 넣지 않는다. URL은 Django url 태그로 연결한다. `/htmx/` 접두어를 모든 프로젝트에 강제하지 않는다.
- CSRF와 서버 폼/권한 검증은 일반 요청과 동일하게 적용한다. 실패한 폼의 bound 값과 오류를 유지한다.
- 4xx/5xx 응답이 기본 설정에서 화면에 자동 반영된다고 가정하지 않는다. 사용하는 HTMX 버전의 오류 처리/응답 교체 동작을 확인한다.
- redirect 헤더, 인증 만료, 뒤로 가기, 로딩과 중복 제출을 필요한 사용자 흐름에서 확인한다. HX-Request 자체를 인증·권한 근거로 사용하지 않는다.
- DOM 교체 후 JavaScript 초기화가 필요하면 기존 프로젝트의 이벤트 패턴을 사용하고 이벤트 리스너를 중복 등록하지 않는다.

출처: [HTMX 문서](https://htmx.org/docs/). 설치 버전의 요청·응답 동작을 확인한다.
