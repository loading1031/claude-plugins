# /planning:done — 기획 브랜치 마무리

먼저 `rules` 스킬을 따른다(기획 설정, 1.5 브랜치). 인자: `$ARGUMENTS` (없으면 현재 브랜치의 항목)

## 절차

1. **대상 확인**: 인자 ID 또는 현재 브랜치로 `backlog.md` "진행 중" 항목을 찾는다. 기본 브랜치에 있고 인자도 없으면 진행 중 목록을 보여 주고 묻는다.
2. **남은 것 확인**: 커밋되지 않은 변경이 있으면 멈추고 `/planning:commit`을 먼저 하자고 한다. 이 브랜치에서 결정했지만 문서에 안 쓴 것이 있는지, 열린 질문이 백로그 후보로 옮겨졌는지 확인한다.
3. **백로그 완료 처리** (기획 브랜치에서): 항목을 "완료"로 옮기고 결과 문서와 날짜를 적는다. `docs: <ID> 완료 처리`로 커밋한다.
4. **합치기 미리보기**: `git log --oneline <기본>..<브랜치>`와 `git diff --stat <기본>...<브랜치>`를 보여 준다. 기본 브랜치가 그사이 앞서갔으면 알린다.
5. **사용자 확인 후 합치기**:
   ```bash
   git switch <기본 브랜치>
   git merge --no-ff <브랜치> -m "docs: <ID> <주제> 기획"
   ```
   - `backlog.md`, `log.md` 충돌은 양쪽 항목을 모두 살려 푼다(log는 날짜순, backlog는 ID순). 그 외 충돌은 내용을 보여 주고 사용자에게 묻는다.
6. **브랜치 삭제**: 합쳐진 것을 확인한 뒤 `git branch -d <브랜치>`. 원격 브랜치가 있으면 지울지 묻는다.
7. **요약**: 합쳐진 커밋, 완료된 항목, 다음 추천 주제(`/planning:backlog`와 같은 기준)를 짧게 보여 준다.

## 규칙
- 합치기와 브랜치 삭제는 사용자 확인 후에만 한다.
- push는 사용자가 요청할 때만 한다.
- `--force`, `reset --hard`를 쓰지 않는다.
