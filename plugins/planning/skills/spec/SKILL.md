# /planning:spec — 결정을 기획 문서에 반영

먼저 `rules` 스킬을 따른다(프로젝트 기획 설정, 템플릿, 작성 원칙, 동기화 표). 인자: `$ARGUMENTS`

## <주제>

### 1. 반영할 내용 확정
1. 이번 대화에서 **결정된 것 / 제안만 된 것 / 열린 질문**을 나눠 보여 준다.
2. 결정된 것만 "결정"으로 쓴다. 제안은 "제안"으로, 열린 질문은 확인 필요 항목으로.
3. **사용자 확인을 받은 뒤에** 쓴다.

### 2. 문서 작성
1. 기준 문서의 한 절로 충분한지, `<주제>.md`로 분리할지 정한다.
2. 분리하면 템플릿으로 새 문서를 만들고, 기준 문서에는 요약과 링크를 둔다.
3. 디스크의 파일이 마지막으로 읽은 내용과 다르면 덮어쓰지 말고 차이를 먼저 보고한다.

### 3. 동기화
동기화 표에 따라 함께 고칠 곳을 모두 고친다. 시각화 문서는 해당 도구로 고치고, 이번에 못 고친 곳은 `backlog.md` "동기화 빚"에 적는다.

### 4. 기록
1. `log.md` 맨 위에 항목을 추가한다(결정, 바뀐 문서, 남은 것).
2. `backlog.md`: 해당 항목을 "완료"로 옮기고, 논의에서 새로 나온 주제는 "후보"에 추가한다.
3. 프로젝트 수준 결정이면 `CLAUDE.md`의 결정 사항을 갱신한다.

### 5. 커밋
`/planning:commit` 규칙으로 `docs:` 커밋을 만든다. 메시지에는 무엇을 결정했는지 쓴다.

## check
1. 기획 폴더 전체와 `CLAUDE.md`를 읽는다.
2. 아래를 찾아 보고한다. **고치지는 않는다.**
   - 같은 대상의 용어·수치·시간이 문서마다 다른 곳
   - 데이터 모델 절끼리, 또는 문서와 시각화 문서 사이의 차이(시각화 문서를 읽을 수 있을 때)
   - 텍스트 다이어그램과 본문 흐름의 차이
   - 프로젝트 용어에서 쓰지 않기로 한 말이 남은 곳
   - 확인 필요 항목 중 이미 확인된 것
3. 발견한 것을 `backlog.md` "동기화 빚"에 넣을지 묻는다.

## 규칙
- 한 번의 spec은 백로그 항목 하나를 닫는다. 여러 주제를 섞지 않는다.
- 사실은 확인한 출처만. 확인 못 한 수치는 "검증하지 않음"과 함께 확인 필요 항목으로.
